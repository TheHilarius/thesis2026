## Code Review — Shortcomings & Issues

Prioritised per ponytail: redundancy, over-engineering, and reinvented wheels first.

1. **Verbatim-copy count keeps climbing — fourth instance of the class** — `src/tools/proteinmpnn/windowing.py:120-180` copies `find_peptide_in_structure` and its three helpers verbatim from `embed_peptides_esmif.py` (acknowledged in the comment), `src/tools/esm/extract_window_plddt.py:80-102` re-implements the ESM-IF chain-choice rule, and `windowing.py:5-21` documents a third window convention (ESM-C's own `make_*_window` functions with a +1 cls offset). The stated justification is real — env_mpnn must not install fair-esm and the ESM-IF module imports esm at top level — but the lazy fix is smaller than the copies: one dependency-free module (pandas/numpy only) holding the locator and window conventions, imported by all three consumers; it satisfies the env constraint and deletes the copies. Same shape as the still-unconsolidated DeLong/Holm helpers. Severity: maintainability. [new instance of carried class]
2. **Four hand-expanded 21-line config dicts** — `config.py:313-391` adds ~84 lines whose entries differ only in checkpoint tag, pad_mode, two paths, and a display name, while the same file already generates keys programmatically (`_AA_EMB_PAIRS`, :703). A ~6-line loop over (ckpt, mode) deletes ~70 lines and makes a third checkpoint a one-token change. Severity: maintainability. [new]
3. **Validator re-implements the embedder it validates** — `validate_embeddings.py:44-66` duplicates `load_model` and the `tied_featurize` plumbing from `embed_peptides_mpnn.py:117-172`, yet :138 already imports `encode_protein` from that module; importing `load_model`/`encode_protein` too removes ~30 lines and keeps the two in lockstep. Severity: maintainability. [new]
4. **Structure audit's guarantee is weaker than its docstring claims** — `audit_structures.py:50` keeps any residue with a CA, while the encoder-aligned selection in `embed_peptides_mpnn.py:146` requires N,CA,C,O, yet the audit docstring (:10-11) says `atom_match` is "what the encoder actually sees"; a protein with a missing backbone atom could audit as ok while the encoder sees a different L. Also `first_resseq != 1` is counted (:178) but never enters the status classification (:79-88), although the docstring (:7-8) names residue numbering as a positional-mapping requirement. The embedder's own sequence+length check (`embed_peptides_mpnn.py:271`) remains the real gate, so this is a documentation/decision-surface risk, not a silent-corruption bug. Severity: risk. [new]
5. **Two doc inaccuracies in the new code** — (a) `vendor/ProteinMPNN_encoder.patch:17` claims h_V is "post-LayerNorm"; the pinned upstream commit 8907e66's `protein_mpnn_utils.py` contains no `layer_norm` anywhere (verified against the raw upstream file), so the embeddings are unaffected but the description is wrong; (b) `config.py:315-316` says the 13 isoform-mismatch proteins "are status=3 (zero-filled)", but the embedder assigns status=1 string-search when the peptide is found (`embed_peptides_mpnn.py:293-310`); status=3 is reserved for genuinely absent peptides, as its own docstring (:22-24) says. Severity: style (interpretation-affecting). [new]
6. **`esmc6b_pca` label hardcodes n_features==781** — `extract_model_metrics.py:68-70` copies the 300M magic number; a 6B run with a different k is silently labelled `esmc6b_full`, corrupting any per-mode aggregation downstream. Severity: risk. [new]
7. **Carried code blockers, unchanged at tip** — (a) `15_padmode_significance.py:79-83` still imports `PADMASK_FILES`/`PADTYPE_MAP`/`load_padded_masks` from `09_padmode_subset_auc.py`, which defines only `load_pad_metadata` (:59) → AttributeError at import; also breaks the reproduce block in `runs/padmode_choice/README.md:118` [bug, twelfth report]; (b) the ESM-IF tuple-unpack crash is now FIXED (72f2984) — first carried blocker resolved in 12 reports, pending a smoke test; (c) `results/tables/slot_vs_flat_leaderboard.tsv` and `slot_vs_flat_results.tsv` still carry 5 references each to the renamed-away `runs/padfull_flat_20261001_1645` [risk]; (d) `.gitignore` still duplicates `runs/*/models/` (:123/:126) and subsumes `runs/slot_legacy/**/*.json` + `runs/slot_legacy/*/*.json` (:141-142) under `runs/slot_legacy/*/` (:143), and `runs/padmode_choice/results/paired_tests_OLD.csv` is still tracked [style]; (e) `run_pca_sweep.sh:2` still documents the nonexistent `run_pca_k.sh` [risk]; (f) `16_esmc300_vs_600.py:196-197` still divides the fold-mean AUC difference by the pooled-OOF DeLong SD and emits the no-op Holm column (`auc_padj = auc_p`) [risk]; (g) DeLong/Holm helpers still inlined in the 807-line `pca_sweep_AUC_delong_comparison.py` and `pca_components: 64` still set across config.py:433+ [maintainability/style]; (h) `src/investigation/README.md` still documents the deleted `10_pad_subset_auc.py`, and neither `pca_sweep_AUC_delong_comparison.py`, `run_encodings_sweep.sh`, nor the new `proteinmpnn/` tools appear in any README [maintainability]; (i) the ESM-C k=17909 log is still zero bytes [risk].
