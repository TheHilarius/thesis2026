## Code Review — Shortcomings & Issues

Ponytail lens: redundancy, over-engineering, reinvented stdlib/native first.

1. **The rewrite makes 09 and 10 near-duplicate scripts — merge them** — 09_padmode_subset_auc.py after 6a98f82 shares the same five helper functions with 10_pad_subset_auc.py (09:55/78/83/122/168 vs 10:52/62/67/92/124, same names and bodies) plus the same pivot/pairwise/save-rows output blocks. Before the rewrite 09 was purpose-built (flat grid, XGB-only, informative mask, toolkit-aware); the README committed hours earlier justified keeping both on exactly that ground ("10's generic CLI could cover 09's grid, but 09 stays purpose-built"). The rewrite removed the purpose-built character and copied 10 instead of pointing 10's CLI at the flat grid — every future bug fix now lands twice. Severity: maintainability. Commit 6a98f82 vs pre-existing 10_pad_subset_auc.py.

2. **Mode-keyed dict silently drops runs in the pairwise and per-row outputs** — 09:286-301 stores `prob_rows[mode] = probs`, keyed by pad mode only. The new pivot table is indexed by PCA value (:366-372), i.e. the intended input is multiple runs per mode (a PCA sweep across campaigns); with such input, every run after the first per mode silently overwrites the previous, and the pairwise Δprob table (:382-420) and `--save-rows` columns (:440-443) report only the last-loaded run per mode with no warning. Same latent pattern at 10:176-184. Key by (mode, pca) or filter explicitly. Severity: risk. Commit 6a98f82 (09:301).

3. **Padded-subset definition changed silently in the rewrite** — the old script's docstring defined the subset as informative rows (≥1 pad AND ≥1 real slot) using per-toolkit masks from the raw embedding H5s, explicitly because "Toolkits' masks differ on notfound rows". The rewrite uses one any-pad mask from the ESM-C prepared H5 (:52, :259) for all runs, including ESM-IF ones, and includes all-pad notfound rows the old script excluded. Any padded-subset AUC computed by the new script is not comparable to the old script's numbers, and the docstring's "~1443 padded rows" (:10) is now unverified. Whether cross-toolkit rows are still aligned is a question for the authors, not answerable from the repo. Severity: risk. Commit 6a98f82.

4. **README's 09 entry is stale by one commit, same day** — investigation/README.md (:169-178 and the relationship map at :268-270) still describes 09 as "No CLI; hardcoded models/flat", "informative mask (≥1 pad AND ≥1 real) from raw H5 + row_indices", "reads xgb only", output `results/padmode_subset_auc.csv`. All four claims are contradicted by 6a98f82 (full CLI, any-pad from prepared H5, model-agnostic globs, TSV outputs). The runnability table row (:258) likewise. Severity: maintainability. Commits 7a9a0bb + 6a98f82.
