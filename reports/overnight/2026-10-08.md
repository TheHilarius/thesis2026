3. **Per-protein flush() in the ESM-C embed loop is redundant I/O** — embed_peptides_esmc.py:604-605 calls `h5s[m].flush()` after every protein. h5py flushes on close; the script has no resume path that would read partial files (the overwrite check at :321-322 refuses to touch existing files), so nothing consumes the intermediate flushes. One flush before the validation block (or none) is the whole job. Severity: style. Commit a67eb62.

4. **Post-run validation re-reads the entire output dataset** — embed_peptides_esmc.py:607-624 scans every row of the first mode's window embeddings in 4096-row chunks computing norms — a full extra I/O pass over the HDF5 at end of run. The guard itself is sound (it catches the all-zero-preallocation failure class that motivated it, and correctly aborts before finalize); the ceiling is end-of-run time for large outputs. A cheaper equivalent: check the first protein's rows non-zero right after writing them. Severity: style (deliberate guard; ceiling noted). Commit a67eb62.

5. **Dead private function in the new comparison script** — 13_compare_slot_flat.py:113-115 defines `_run_timestamp(name)` but nothing calls it (collect() reads `d.get("timestamp")` from the JSON instead). Dead code in a brand-new file. Severity: style. Commit 01e5a32.

The docstring acknowledges this ("partner's expanded sweeps / legacy values"), so it is a deliberate scope filter — but the ceiling is silent scope drift: if a sweep is re-run with new values, the script quietly reports fewer cells instead of failing. Severity: maintainability (low, documented ceiling). Commit 01e5a32.
