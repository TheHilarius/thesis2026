## Experiments / Results

Repository-supported results only (all from committed TSVs; every row has `has_heldout_predictions=False` — see review finding 3 on the `heldout_*` columns).

**Slot-mode baselines** (`results/tables/slot/model_matrix_lr_l2_rf_xgb_20260926_004934.tsv`, 6 runs, nested CV):
- handcrafted (52 features): rf AUC-ROC 0.583 ± 0.008, lr_l2 0.566 ± 0.008, xgb 0.566 ± 0.006
- handcrafted_sparse (683 features): rf 0.692 ± 0.006, lr_l2 0.710 ± 0.006, xgb 0.741 ± 0.004

**Flat-mode ESM-C window results** (`results/tables/flat/`, 20 unique runs; feature set `handcrafted_sparse_esmc_win_*`, k∈{10,97,469}):
- Best committed: xgb, zeropad, k=97 (780 features) — AUC-ROC 0.752 ± 0.005, AUC-PR 0.712 ± 0.008, MCC 0.372 ± 0.011
- padtoken k=97: 0.753 ± 0.005; impute_bos_eos k=97: 0.752 ± 0.006
- Within a mode, k=10→469 changes AUC-ROC by ≤0.006 (xgb); at matched model and k, the three fully-reported modes differ by ≤0.003 — all within fold-to-fold std.
- Against baselines: xgb +0.011 (0.752 vs 0.741), lr_l2 +0.005 to +0.023 (0.715-0.733), rf flat 0.686-0.694 ≈ rf baseline 0.692 (rf gains ~nothing from windows in flat mode).
- Observation (design note from a259a05): flat PCA fits only fully-real rows, identical across zero/boundary/eos_bos_repeat modes, so the flat comparison isolates each mode's transform-time fill effect; padtoken's real slots are RoPE-shifted, so its basis differs by construction.

**Not yet committed:** no slot-mode window rows (only baselines) and no ESM-IF flat rows — the winmat_slot/winmat_flat batches are not aggregated in the committed tables. Nested-CV structure verified sound: PCA is fit inside `prepare_fold` on inner-train indices only (`04_modelling.py:1283-1286`, `validation_bucket=outer_fold`), so no PCA leakage into validation.

## Code Review — Shortcomings & Issues

**1. Stale pre-rename ESM-IF inspection outputs restored under windows_test/**
`results/embedding_inspection/windows_test/comparison_table.csv` (deleted in 2aa4ee1, re-added in fb7d822) contains the OLD 3-mode ESM-IF names (`esm-if_test_padtoken`, `esm-if_test_eosrepeat`) plus legacy context-embedding rows — mode names that no longer exist in config (renamed in the 46d8c7b/958ac26 range). It now sits beside the current `esmif_all4/`, giving two ESM-IF window-inspection directories with contradictory mode names. Citation hazard for the thesis. Fix: delete `windows_test/` or move it out of `results/`.
Severity: risk. Commits: 2aa4ee1 (delete), fb7d822 (restore).

**2. Fully-real-row selection logic duplicated between analysis and modelling**
`src/investigation/08_pca_variance_analysis.py:180-206` (`keep = fully_real & (norms > 0.0)`, line 203) reimplements the row filter inside `src/pipeline/python/04_modelling.py:528-580` (`fit_window_pca_flat`). The 08 docstring asserts it is "the same mode-invariant subset", but nothing enforces that — and 08 already puts the pipeline dir on `sys.path`, so importing one shared filter is a one-line change. If either copy changes (e.g. the zero-norm condition), the variance curves silently describe a different population than the fits that consume the sweep k values derived from them.
Severity: maintainability. Commit: a259a05.

**3. `heldout_*` columns in committed TSVs are not held-out results**
`src/pipeline/python/extract_model_metrics.py:127-130` — when `held_out_metrics` is absent, `heldout_*` falls back to the mean of `outer_val_metrics` (nested-CV outer validation). Every committed row has `has_heldout_predictions=False` and `heldout_auc_roc == cv_mean_auc_roc` (e.g. all rows in `results/tables/flat/model_matrix_lr_l2_rf_xgb_20260927_114333.tsv`); the table also sorts by this column (lines 158-162). A reader (or thesis text) could quote "held-out AUC 0.752" when no independent held-out evaluation exists. The fallback is documented in code, but the column name in the output is not.
Severity: risk (presentation). Script is pre-existing; the first committed result tables expose it.

**4. Zero-byte log files committed again (third recurrence)**
`logs/04_modelling_rf_handcrafted_sparse_esmc_win_impute_bos_eos_pca148_log_20260925_115419.txt` and `logs/04_modelling_rf_handcrafted_sparse_esmc_win_zeropad_pca26_flat_log_20260925_140651.txt` (fb7d822, both 0 bytes). Three zero-byte logs total at origin. The pca148/pca26 names also no longer match any sweep value in the final scripts (slot: 9/334/742; flat: 10/97/469) — they are abandoned sweep guesses. Previous reports flagged this twice; it recurred.
Severity: maintainability. Commit: fb7d822.

**5. Stale hardcoded DEFAULT_COMBOS in the matrix runner**
`src/pipeline/python/04b_run_matrix.py:37-70` — 30 legacy combos (context-embedding feature sets at pca=1/9, "50% variance" values), used only when the script is invoked with no `--combos`/`--pca-sweep` (line 242). Every current SLURM script passes explicit args, so this is dead config that would launch 30 legacy runs if 04b is run bare. Delete it or update it to the current window matrix. Related style: `src/run/run_matrix_windows_slot_slurm.sh:31-32` hardcodes `ESMC_PCA`/`ESMIF_PCA` while the flat sibling (`run_matrix_windows_flat_slurm.sh:29-30`) allows env overrides.
Severity: maintainability. Commits: a259a05, d3ee9d6.

**6. Defensive matplotlib guard inconsistent with the rest of the repo**
`src/investigation/08_pca_variance_analysis.py:34-40, 257, 305` — `HAS_MPL` try/except with per-plot skip paths. Every other plotting script in the repo imports matplotlib unconditionally (`05_model_analysis.py`, `06_feature_importance.py`, `07_compare_heldout_roc.py`, `09_sequence_consistency_audit.py`, tools). Either matplotlib is a hard dependency (import it unconditionally) or the server env is broken (fix the env) — silently skipping plots lets a "completed" analysis produce no figures.
Severity: style. Commit: a259a05.

**7. Flat-PCA working set is a hard memory/runtime ceiling (deliberate, named)**
`src/pipeline/python/04_modelling.py:528-580` — `fit_window_pca_flat` materializes all fully-real rows as float64 before fitting (~45k rows × 33,408 dims ≈ 12 GB for ESM-C). It runs once per inner fold (6 outer × 5 inner = 30 fits per modelling run; 04b runs 9 model×k combos per array task ≈ 270 flat fits per array job — this is what the 96h limit buys). Justified in the docstring and within the 64G SLURM budget, but flagged as the ceiling: if the split grows, the upgrade path is float32 or chunked PCA on the fully-real subset.
`# ponytail: full float64 materialization of ~45k×33k rows, ~12GB/fit; switch to float32 or chunked PCA when the split outgrows 64G`
Severity: risk (ceiling, not a bug). Commit: a259a05.

## Potential Issues

1. **Pad-count features now silently part of every feature set, including baselines.** `04_modelling.py:1155-1165` adds `n_pad`/`c_pad` derived from coordinates; the split data (`data/processed/df_all_with_folds.csv`) has `start`/`end`/`protein_length` but no `n_pad`/`c_pad` columns, and `get_feature_cols` (config.py:544-546) excludes only metadata + position-AA columns — so both derived columns enter `csv_feature_cols` for all feature sets. The committed baseline showing 52 handcrafted features is consistent with 50 + 2. Questions for the authors: (a) is it intended that mode-independent baselines carry pad-count context features, making them comparable only to other post-a259a05 runs? (b) does the hardcoded 10-flank assumption hold for every split row, and do the coordinate-derived counts equal the pad_mask sums the old window-block features used?
2. **Committed result tables are partial.** Flat TSVs cover ESM-C only; the slot table covers baselines only. The ESM-IF flat sweeps (76/345/851) and both slot window sweeps have no committed aggregates — scripts run with `--no-aggregate`, so a manual `extract_model_metrics.py` pass per batch is needed (e.g. `--results 'models/flat/cv_results_*.json'` and `--results 'models/slot/cv_results_*.json'`).
3. **Zero-byte/abandoned logs keep accumulating** (review finding 4). Candidates: stop committing `04_modelling_*.txt` logs entirely, or a pre-commit size check.
4. **windows_test/ stale directory** (review finding 1) — one delete removes the hazard.
