**Significance** (paired_tests.csv, 44 pairs): no padmode pair is significant after Holm on the padded subset (all 12 DeLong CIs span 0; ESM-C within ±0.030, ESM-IF within ±0.032; full-data padmode CIs within ±0.004). sparse vs blosum on full data: ΔAUC = −0.0223, DeLong CI [−0.0247, −0.0200], z = −19.0, p ≈ 4e-80 (BLOSUM50 beats one-hot); on the padded subset the sign flips to +0.0053, p = 0.51. The README states explicitly that non-significance is not equivalence and that all inference is conditional on one CV partition.

## Code Review — Shortcomings & Issues

Ponytail lens: redundancy, over-engineering, reinvented stdlib/native first.

1. **15_padmode_significance.py cannot run at tip — it imports three names 09 no longer defines** — 15:80-83 does `PADMASK_FILES = _mod.PADMASK_FILES; PADTYPE_MAP = _mod.PADTYPE_MAP; load_padded_masks = _mod.load_padded_masks` from 09_padmode_subset_auc, but committed 09 defines none of them (09 has DEFAULT_PAD_H5:52, load_pad_metadata:55, a single any-pad mask at :259). `import` raises AttributeError immediately, so the README's reproduce step (runs/padmode_choice/README.md:118) fails, as does any rerun of the significance CSV. This is the residue of the 09 rewrite (6a98f82) that dropped those names after 15 was written against the old API. Severity: bug. Fix by restoring the per-toolkit mask helpers in 09 or hoisting them into one module that 09/14/15 all import.
2. **The committed padmode_subset_auc.csv was produced by no committed script** — the CSV's schema (toolkit,padtype,learner,pca,auc_padded,n_padded,...) and its per-toolkit row counts (1443 vs 1442) match the informative per-toolkit mask (≥1 pad AND ≥1 real) that 14_plot_grid_auc.py:225-238 implements, not tip 09 (single any-pad mask from one ESM-C prepared H5, TSV output with mode/result_file/pad_auc_roc columns, 09:259/:305-357). The README's reproduce block compounds this: it invokes 09 with `--models-dir` (:115-117), an argument 09 does not accept (09:174-204 offers --results/--since/--out/--pad-h5/--save-rows). Anyone re-running gets a different mask, a different schema, or a CLI error. Severity: risk (reproducibility of headline numbers).
3. **Three implementations of pad-mask loading + OOF reconstruction, in one commit** — 09 (load_pad_metadata:55, reconstruct_probs:122), 14 (PADMASK_FILES:90, load_padded_masks:225-238, assemble_oof:246-271), and 15 (reconstruct_oof:104-118, mask imports from 09). The three already disagree (any-pad vs informative; one mask vs two). One ~40-line shared helper module deletes the duplication and structurally prevents finding 1. Severity: maintainability.
4. **Duplicated statistical helpers across 14 and 15** — Holm (15:180-197) vs BH (14:_bh), fold-paired t-tests with zero-variance guards (14:_paired_t vs 15:fold_t_nb), OOF size/finite checks. Two scripts, same commit, same maths, two code paths to drift. Same shared module as item 3. Severity: maintainability.
5. **investigation/README.md documents a file deleted in the same range** — 10_pad_subset_auc.py is referenced at :13, :33, :139-141, :248, :262 ("both kept") and in the runnability table :289; the :262 description of 09's mask ("informative mask from raw H5 + row_indices") also still contradicts tip 09. The previous report's stale-README finding has worsened from "one commit behind" to "documents deleted code". Severity: maintainability.
6. **Redundant committed artifacts** — paired_tests_OLD.csv is a superseded duplicate of paired_tests.csv kept in the working tree (git history already preserves it); model_matrix_padmode_11.tsv vs model_matrix_padmode.tsv differ only in row count with an opaque suffix; run_prepare_windows_slurm.sh:25-27 comment still says "Re-prepare all 8 window embeddings … overwrites the stale ESM-IF prepared files" while the command below it prepares only the four esmc300m keys.
